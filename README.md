# MAD Lab — Original Flutter Applications

This repository contains six **different application ideas** that demonstrate the same categories of Flutter features as the six projects in the reference MAD Lab repository. The themes, UI copy, data models and app behavior are independently designed; this is not a renamed copy of the reference projects.

## Six projects and feature coverage

| Project | New application idea | Required feature set demonstrated |
|---|---|---|
| `campus_companion` | Campus Companion | Flutter app structure, Material widgets, StatelessWidget / StatefulWidget, layouts, state updates with `setState`, TextField, dropdown, Switch, NavigationBar, SnackBar |
| `book_exchange_manager` | BookLoop — Book Exchange Manager | Firebase Core initialization, Realtime Database, push/set/update/remove, live `onValue` stream, StreamBuilder, create/edit/archive/restore/delete, category/course metadata |
| `campus_event_board` | Campus Pulse — Live Event Board | Firebase Core initialization, TextField input, Realtime Database push/set/remove, live StreamBuilder feed, SnackBar feedback |
| `travel_explorer_dashboard` | Roamly — Travel Explorer Dashboard | Material icons, bundled local image asset, network image with fallback, image layout, `fl_chart` bar chart |
| `expense_file_lab` | Pocket Ledger — Expense File Lab | `path_provider`, app documents directory, Dart file write/read, `FutureBuilder` loading/error/success states, `SharedPreferences` web fallback |
| `museum_explorer` | Museum Explorer | Named routes, `Navigator.pushNamed`, `MaterialPageRoute`, `Navigator.pop`, route arguments, GestureDetector tap/double-tap/long-press, stateful controls, SnackBar |

## Requirements

- Flutter stable SDK and Dart 3.3 or newer
- Android Studio or VS Code with Flutter extension
- Android emulator or Android phone
- Internet access for dependency downloads and the network image demonstrations

## Prepare and run

Each folder is a separate Flutter project. From the root directory, run the following inside each project folder:

```bash
cd campus_companion
flutter create . --platforms=android,web
flutter pub get
flutter run
```

Repeat for the other five folders. The generated Android and web platform scaffolding is intentionally not bundled so Flutter can create platform files compatible with your installed SDK.

## Firebase configuration

`book_exchange_manager` and `campus_event_board` require your own Firebase project. For each folder separately:

1. Create a Firebase project in the Firebase Console.
2. Register an Android app using the Android application ID generated by `flutter create`.
3. Enable Realtime Database and select an appropriate database security policy. For a classroom demo, use test rules only in a controlled environment; do not expose production data publicly.
4. Install/configure FlutterFire:

```bash
dart pub global activate flutterfire_cli
flutterfire configure
```

5. Select the Firebase project and Android app. FlutterFire generates `lib/firebase_options.dart`; this replaces the placeholder included here.
6. Run `flutter pub get` and `flutter run`.

Do not add service-account private keys to GitHub. The placeholder Firebase options deliberately contain no credentials.

## Notes

- This repository is a learning starter, not a claim that all six apps have been built or emulator-tested on your machine.
- Firebase apps cannot connect until configured with your own Firebase project.
- The travel dashboard uses a local bundled illustration and a separate network image.
- The expense file lab uses app-private storage on native platforms; browser builds use SharedPreferences as a browser-storage fallback.
- Run and test every app before your lab submission, and make sure you can explain the feature checklist above.
